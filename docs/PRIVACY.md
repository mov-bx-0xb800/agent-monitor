# Local data and privacy

Agent Monitor has no internet client, telemetry or direct model API requests. Its experimental Codex adapter opens a bounded local Unix socket only for a focus submission. Its local hooks can see an event payload transiently to select metadata and images. General event payloads are not logged.

Stored data includes the agent name, a hash of the session identity, bounded native session/subagent identifiers for exact routing, workspace path, short first-prompt-derived chat label (up to 90 characters), last activity time, inferred areas with a confidence and a short reason (such as “auth” in path), an observed path or recognised-command label, queued category IDs and delivery status and cached raster images. A command label names only a recognised program and a known subcommand or script name, such as `npm run lint` or `cargo clippy`; arguments, flags, URLs, environment values and unrecognised words are never kept. Paths outside the workspace are kept for display, with the home folder shown as `~`, but classified by file name only. Bounded adapter diagnostics retain an event receipt timestamp, a short workspace path and a failure code; they contain no raw event payload. The short label can contain prompt text. Labels, titles and paths are redacted for common credential shapes (API keys with known prefixes, cloud access keys, GitHub, GitLab, Slack, Stripe and npm tokens, JWTs, bearer and basic credentials, private-key headers, `password=`/`token=`-style values and credentials in URLs), but sanitisation is best effort, not a guarantee that every secret is removed. Full prompts, reasoning, code bodies and transcripts are not retained. Image contents and paths can contain private information; “local” does not make them non-sensitive.

The sidebar and main editor view filter activity, images and adapter diagnostics by workspace. Diagnostic records with no matching workspace are omitted; diagnostic workspace paths are not sent to the views. The shared collector can hold other local workspaces within the same global limits. Another application running as the same operating-system user may be able to read those files. POSIX files/directories request private modes; Windows uses the user's application-data directory and inherited ACLs. The cache is not encrypted by this extension.

Settings backups contain the original agent configuration and may therefore contain sensitive values. Keep them local. They are never bundled in the extension or repository. One adjacent `.agent-monitor-backup` is maintained per settings file; subsequent changed configurations replace that backup.

The helper stores at most 12 recent chats and 20 images within the documented budgets. Each chat also keeps its focus progress for as long as the chat is retained: one evidence total per area with its last-seen time, the current minute's totals, 32 subject hashes with their areas, a few short hashed keys for deduplicating the current minute, and the last 32 hashed tool-call IDs. No code, prompt text, command text or tool output is stored for scoring. Chat metadata is pruned on collection and filtered from display after 24 hours. Images remain until dismissed or evicted by storage limits. Pause stops new collection, diagnostic writes and request delivery without removing stored data. Focus requests are bounded to 24 records, expire after one hour, and are never automatically repeated. The helper emits a fixed context-aware instruction only after a user clicks Focus here; it does not read agent transcripts.

Disconnect hooks before uninstalling, then end agent sessions that may still have the old hooks loaded. To erase the collector cache, remove Agent Monitor's application-data directory. Adjacent `.agent-monitor-backup` files and editor workspace state are separate: deleting the cache does not remove them. Remove only Agent Monitor's adjacent backup files if they are no longer needed; never remove the agent's settings file or other hook handlers. The extension currently has no complete erasure command for editor workspace state. Local chat-name overrides, category selections and layouts remain in the editor's workspace storage; uninstalling or deleting the collector cache must not be presented as erasing them. Editor backups may also retain copies.

Custom areas are defined in `.agent-monitor/focus.json` in the workspace, which a team may commit. **Start now** opens a short form in the card. What you type stays in that form and is not saved; the view remembers only which agent you chose last. **Create Focus Area** writes `.agent-monitor/GUIDE.md` (a copy of the drafting guide) unless a file someone else wrote is already there, and passes the name, details and field you entered, redacted for common credential shapes, to the agent you chose, in a terminal or on the clipboard. In a terminal the request is typed as a command, so your shell may keep it in its history; **Copy instructions** avoids that. Agent Monitor itself sends nothing anywhere. Enabled definitions and the project's stakes are copied into `profiles.json` in the local cache; approvals (a content hash per folder), dismissals and the stakes choice are kept in editor workspace state. A focus request for a custom area stores its label and description (bounded and sanitised) so delivery does not depend on workspace files. **Copy fix request** puts the local check's findings on the clipboard. A definition from a cloned repository does nothing until someone approves it.

Visible category selections are stored in the editor’s local workspace state, keyed by hashed chat identity. Saving a selection retains only current workspace chats (at most 12) and the 13 recognised category IDs. Choosing areas sends no instruction to an agent.

Local chat-name overrides (up to 90 sanitised characters) and ordered area layouts are also stored in editor workspace state. Saving prunes unknown/stale chat entries; layouts contain only recognised category IDs, with one additional All chats layout. Renaming changes only the local display. First-observed timestamps and a subtask flag are stored as bounded chat metadata.

Native routing identifiers are excluded from sidebar messages. The Codex bridge discards unsolicited IPC broadcasts and never logs protocol bodies. A user-requested follow-up is processed by the existing provider chat and can consume that provider's normal usage allowance.

On macOS, connected Claude chats may hold a private FIFO and a small lease record (hashed chat ID, random token, process ID and expiry). At most twelve listeners wait for one hour each. The FIFO carries only a request ID; the fixed focus instruction is built at delivery. Node is not kept running per listener. Pause, disconnect and session end cancel ready listeners.

To show the same chat names as the agent, the editor reads titles from the agent’s own local files: Codex’s `session_index.jsonl` and the `ai-title`/`custom-title` rows of a Claude Code session file (at most its last and first 1 MiB). Only those title rows are parsed; no other content from those files is read into the view, stored or sent anywhere, and titles live only in editor memory. Cursor titles are not read.

“I don’t use …” choices are stored in the editor’s global state as adapter keys only (`codex`, `claude`, `cursor`). They affect setup warnings and change no hooks. The time of the latest image seen in Images is kept in that view’s own state to show the unseen-image count; it is not written to the cache or sent to agents. **Main Window** opens a local editor tab showing the same filtered data; it adds no network access or storage.

Images are cached from supported image bytes returned by successful post-tool events. There is one exception, because Codex replaces image data in hook payloads with a placeholder: after a successful Codex `view_image` call, the helper reads the one file that call named. It never follows a link or opens a folder, device or pipe. The name must be a PNG, JPEG, WebP, GIF, BMP or AVIF file within the 24 MiB image limit, and the file is kept only if its contents decode as a supported image. No other tool or path field is ever opened. Images that other Codex tools return, such as screenshots from code execution, reach the model but not the hook, so they cannot be shown. Older cached images without this provenance marker are hidden immediately by the updated extension and their hash-named cache copies are removed on the next collection by the updated helper. When the extension starts, it refreshes an already installed helper with its own bundled copy if that copy is newer or differs, so collection fixes apply without reconnecting. This replaces only Agent Monitor's helper files; it does not edit agent settings or hook commands, and a helper written by a newer installed version is left alone. Editing this repository does not update an installed helper until an editor with the changed extension starts or Connect runs. Pausing preserves old cache files until collection resumes or they are explicitly removed.
